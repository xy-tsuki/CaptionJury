# 开发日志

新的在上面。

## 2026-11-11
- 精度优化的顺序改成：备用模型 → DeepSeek 大纲 → Qwen 复核（带大纲里的术语）→ DeepSeek 校对。大纲的输入附上备用模型和 MOSS 写法不同的地方。
- 查明上一轮"大纲失败"的原因：之前跑字错率时测试脚本在设置 `TINGXIE_HOME` 之前导入了 `core.store`，把假 DeepSeek 地址和测试密钥写进了本机真实设置。已恢复地址、删掉测试密钥（用户的原密钥要重新填），并在 `tests/local_models.py` 加了检查，数据目录不是临时目录就停下。
- 审阅页每条字幕可以改入点出点（输入时间码、±0.1 秒、设为播放位置）、播放这一条、删除（可撤销）。
- Qwen 漏掉、其他模型听到的段落不再丢掉：按字数估时间，插到前后两句之间，标成存疑，Qwen 一栏显示"没有结果"。不让模型重听，多余的由用户删。2 分钟片段（MiMo + Whisper + 说话人区分，假 DeepSeek）插了 8 条，大多是真漏掉的话（"这是国内的""要不要看""ないよ"），也有切分边界上的半句（"几种东"）。
- 修复：有几句字幕时间是 00:00:00。原因不是语言设置，而是 Qwen 漏听了块开头的一段，对齐模型对不上，把前 31 个字的时间都堆在块开头（0 秒）。现在连续 3 个以上长度为 0、时间相同的词当作没有时间，按每字 0.2 秒排在最近的有时间的字旁边；中间空得远超正常语速时紧跟前一个字，不再摊满整段；句子起止取第一个和最后一个有效字（没有时间就用估算的）。出现这种情况时任务里加一条警告。用三个真实任务重放：句数 211→219、33→34、285 不变（堆在中间的那些字被拆成了单独的句子），没有重叠和零长度的字幕；其余句子的结尾大多提前 0.04–0.1 秒（不再算上和最后一个字共用时间的标点）。

## 2026-11-10
- 启动方式从 run.bat 改成安装包：PyInstaller 打包成 Tingxie.exe，Inno Setup 生成 `Tingxie-Setup-<版本>.exe`（约 71 MB，含 FFmpeg 9.0.2）。安装时可选只为当前用户或所有用户；没有 WebView2 时顺便装上；卸载时问要不要删模型和设置。
- 首次运行引导页：检测显卡和驱动，推荐 CUDA 或 Vulkan；运行库从 CrispASR 官方 Release 下载并解压，必装模型走原来的下载器。Issue #1 里"运行库不能在程序里下载"这一项做完了。
- 发版改成推送 `vX.Y.Z` tag，由 CI 构建安装包并发 Release；dev 上改打包文件时 CI 也会构建一次（不发版）。
- 验证：本机打包的 exe 在全新数据目录下进入引导页，从官方下载 Vulkan 运行库后转写 30 秒片段正常；CI 构建的安装包静默安装、启动、卸载都正常。没有试过安装向导的界面（中文页面、"所有用户"选项、卸载时的删除提示），也没有在没装 WebView2 的电脑上试过。
- 上传 GitHub 备份 Release `models-v1`：7 个模型的 10 个附件（Qwen 2 卷、MiMo 3 卷）加两份许可证全文，Release 不标为最新版本。说明里写了每个文件的来源仓库、原始模型、许可证和"已量化"。
- 上传前逐个核对大小和 SHA-256。本机的 Qwen 文件（`E:\AI\Qwen3-ASR-1.7B-OASR`）和 HF 上的不是同一版，多 1568 字节，所以改从 HF 重新下载后上传。
- 查了各模型许可证，全部是 Apache-2.0 或 MIT，见 `docs/model-licenses.md`。
- 本机的 Qwen 换成 HF 版（`E:\AI\Qwen3-ASR-1.7B-GGUF`）。同一套代码在小米眼镜片段上对比：旧文件 21.59%，HF 版 22.03%，参考稿 454 字，只差 2 个字，算不上差别。之前记录的 21.6% 是用旧文件测的。

## 2026-11-09
- 仓库改为公开；私人录音的参考稿移出仓库，只留在本机。
- 新增模型清单 `core/models.py`，默认路径改到数据目录，不再写死 `E:\AI`。
- 每种语言可以同时启用多个备用模型，接入 Whisper；设置页按语言勾选。
- 修复：没有标点的备用结果（Whisper）按句切分时每句错位一个字。
- 模型下载器：设置页选来源下载，断点续传、SHA-256 校验、失败自动换源；三个来源是 Hugging Face、hf-mirror 镜像、本项目 GitHub 备份（尚未上传）。
- 建立 git 仓库和 GitHub 私有仓库，补 AGENTS.md、开发日志、决策记录、CI 和 PR 模板。
- 新增字错率评测 `tests/cer.py`，用户校对好了小米眼镜片段的参考稿。
- 切块改成按总长平均分：原来最后会剩一小块（8 秒），Qwen 几乎什么都没听出来。Qwen 的字错率从 23.4% 降到 21.6%。
- 试过但没采用：响度标准化、20 / 25 秒块、5 秒重叠、本地逐字投票。前三个的结果随参数在 20% 到 24% 之间来回变，算不上稳定的提升；投票只提升约 0.5 个百分点。
- 估算上限：至少有一份结果听对的字占 91%，Qwen 单独只对 78% 左右，剩下的提升要靠合并几份结果。
- DeepSeek 校对改成分批并发（每批约 30 句，带前后文），并加程序校验：结构错误打回重写一次；内容和各份识别结果对不上的标成存疑，交给用户选。提示词加了示例。
- 对比 Whisper large-v3 q5_0：小米眼镜片段的字错率 28.6%（Qwen 21.6%），结尾凭空多出一句话；东京片段 37 秒以后时间戳全乱。但它的错误和 Qwen 不同，速度又快，适合当备用模型。
